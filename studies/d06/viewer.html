d06：從 Prompt 修改追蹤 Agent 失敗路徑

比較實際送出的 system prompt

依完整文字的 SHA-256 去重。每個快照包含當時的工具描述與 Parameters JSON Schema。

閱讀方式與一致名詞

完整 run
agent 處理一次原始問題；可包含多個主 turn、工具執行與 aux requests。
Turn
一次主 LLM request / response。工具內的 aux 不另外增加主 turn。
Request / prompt
Request 的 messages 是模型輸入；含 system、原始問題、先前 completion 與工具 feedback。畫面中的「完整 request」不刪除重複歷史。
Completion
本頁指 response.message.content，也就是模型輸出的文字，可能包含工具呼叫。完整 HTTP response 若有保存，可另外展開。
Tool calling
分開記錄「解析出的意圖」與「實際執行狀態」。合法不代表執行過；執行成功不代表答案正確。
Probe / replay
只觀察一次主 request 的決策，不執行工具。replay 使用保存的歷史；原 turn 4 在重播 recorder 中是第 1 個 request。
Aux request
工具內部額外呼叫模型，例如 email_qa；完整輸入與 completion 另外展開，不能重複計入主 turns。
Tokens
Native 數值來自 Ollama HTTP response；課程估算來自字元數計算，兩者不同。未保存 native 數值的歷史紀錄標示「未記錄」。

事實、解讀與限制

  • 觀察：直接來自 request、completion、tool result 或原始設定。
  • 解讀：研究者對錯誤模式的歸納，與原始輸出分開呈現。
  • done 只表示流程結束。日期字串比對也不是完整語義評分。
  • 本紀錄只涵蓋 d06 與既有本機模型測試；不是 Problem 9 的 20 題整體成績。
  • temperature=0 的重複呼叫不是獨立統計樣本，且控制重播的 completion 曾未逐字一致。
  • 歷史紀錄未全部保存 HTTP JSON、模型 digest 或完整程式碼快照；未知處保持未記錄。應用程式 messages 不等於可直接觀測後端最終 token 序列或模型內部推理。
  • 畫面只解讀資料文字，不執行 retrieved text 中的 HTML、Markdown 或指令。
